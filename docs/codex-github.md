# CodexのGitHub運用

## 公式連携で使う機能

[公式GitHub連携ドキュメント](https://developers.openai.com/codex/integrations/github)では、PRの自動レビューと、レビュー後の修正依頼をサポートしている。修正依頼はPRを文脈にしたクラウドタスクを起動し、権限があればPRのブランチへ修正をpushできる。AGENTS.mdはそのタスクの作業方針を定めるもので、GitHubイベントの購読や認証・権限の設定は行わない。

## 設定

1. GitHubリポジトリ `4k29/-orchard-feed` をCodexへ接続し、連携に対象リポジトリへのアクセスを許可する。
2. [Codex設定](https://chatgpt.com/codex/settings)で対象リポジトリの **Review code → Automatic review** を有効にする。自動レビューの設定変更にはGitHubのpushまたはadmin権限が必要。
3. **Personal preferences → Automatic review** と **Review trigger** も確認し、レビュー対象のPRと起動タイミングを選ぶ。
4. 修正タスクが対象リポジトリで実行でき、PRのheadブランチへpushできる環境・権限を確認する。フォークのPRや保護されたブランチでは書き込みできない場合がある。権限不足を解消するためにブランチ保護を無効にしたり、広い権限のPATを追加したりしない。

これらはCodex/GitHub側の設定であり、リポジトリ内のファイル変更では有効化されない。この整備ではCodex側の設定状態や修正タスクの実行権限を取得できておらず、自動レビューが有効とは断定できない。

## レビューから同じPRへの修正

- 手動レビューはPRコメントに `@codex review` と記載する。
- 指摘を修正する場合は、そのレビューコメントへの返信で `@codex この指摘を修正して、同じPRのブランチに反映してください` と依頼する。複数の指摘がある場合は対象を明示する。公式の例は `@codex fix the P1 issue`。
- `@codex` だけでは修正対象・意図が曖昧になるため、修正依頼を添える。`@codex review` は再レビューの依頼であり、修正の依頼とは区別する。
- Codexは指摘を確認して修正・検証し、同じPRへ反映する。pushできない場合はその理由を報告する。修正後もAGENTS.mdの方針に従い、必要な検証とGitHubの必須チェック・承認条件を満たしたら、都度確認なしで同じPRをマージする。

導入時には代表的なPRで `@codex review` を実行し、修正依頼への反応、クラウドタスクの起動、同じheadブランチへのコミット、検証結果を確認する。反応がなければ接続先リポジトリ、Codexのレビュー設定、依頼者の利用権限を確認する。この文書の追加だけでは一連の動作を検証したことにはならない。

## Actionsを追加しない理由

既存のActionsはRSS・製品・OSデータ更新とPages公開を担当し、レビューコメントを処理する仕組みはない。公式連携が上記の運用を提供するため、今回レビュー用ワークフロー、Webhook中継、外部サービス、追加secretは導入しない。公式連携で対応できない具体的な制約が判明した場合に限り、実行者の認可、最小権限、外部PRの隔離、秘密情報の保護を含めて追加の仕組みを検討する。
